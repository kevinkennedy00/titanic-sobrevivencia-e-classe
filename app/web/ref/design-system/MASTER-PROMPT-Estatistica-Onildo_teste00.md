MODO DARK OBRIGATÓRIO
Este requisito é vinculante e não pode ser ignorado ou simplificado.

O Design System resultante DEVE implementar modo escuro como primeira prioridade visual, não como afterthought:

1. PALETA: O modo dark é a paleta canônica deste projeto. Fundos escuros profundos (não cinzas genéricos) com textos e elementos de alto contraste acessível. Tokens de cor definidos explicitamente para ambos os temas; o dark é o padrão inicial ao carregar a página.

2. ALTERNÂNCIA: Botão de alternância dark/light funcional, acessível via teclado, com estado persistido em localStorage. O label e o ícone comunicam claramente o tema ativo.

3. COMPONENTES: Cada componente, token, card, tabela, formulário, overlay, modal, sidebar e navbar deve ter variante dark explicitamente implementada — não como inversão automática de cores, mas como decisão visual intencional.

4. CONTRASTE: Ratio mínimo WCAG AA (4.5:1 para texto normal, 3:1 para texto grande e elementos UI) verificável em ambos os temas.

5. PREFERS-COLOR-SCHEME: O tema respeita a preferência do sistema como fallback, mas o botão de alternância tem precedência sobre qualquer valor do sistema.

6. ASSETS: Logos, ícones e imagens que precisem de tratamento diferente no dark têm suas variantes declaradas — não são simplesmente invertidos com filter.

A ausência ou implementação superficial do modo dark reprovará a fase automaticamente, independentemente de qualquer outro critério.
